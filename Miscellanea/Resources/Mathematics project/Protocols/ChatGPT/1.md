## ChatGPT Transcription Protocol (Obsidian + LaTeX)

This page is the canonical “transfer packet” for setting up a new ChatGPT chat (or account) so it matches my established workflow for transcribing and transforming handwritten mathematical notes into Obsidian-ready Markdown + LaTeX.

---

### 0) Personal context that matters for this workflow

- Preferred name: **Dunn**
- Core use-case: building a long-lived **Obsidian vault** (“second brain”) for math
- Preferences that affect output:
  - **Rigor** and correct hypotheses/domains
  - **Consistency** across documents and topics
  - **Copy-paste readiness** with minimal/no manual repair
  - **Explicit corrections**: do not silently fix my math; flag and explain corrections
  - Avoid filler; write like a smart human (not “politice robot” / not AI-ish)

---

### 1) Absolute formatting invariants (apply to everything)

#### 1.1 Obsidian readiness

- Output must be **Obsidian-friendly Markdown + LaTeX**
- Display math uses **only**:
  - `$$ ... $$`
- Do **not** use:
  - `\[ ... \]`
- When I ask for “paste-ready code,” return the content inside a fenced block:
  - Use one fenced block of type `markdown` per requested item so it does not render in chat

#### 1.2 LaTeX restrictions (hard rules)

- **Never use `\tfrac`**
- Use `\frac` / `\dfrac` only
- Prefer `\dfrac` for displayed fractions (especially in aligned/proof blocks)
- Use `\lvert \cdot \rvert` inside tables (Obsidian treats `|` as column separators)
- For equivalences:
  - Use `\Leftrightarrow`
  - In aligned chains: `\quad \Leftrightarrow \quad`

#### 1.3 “Two-font” rule for image → LaTeX (proof)

For image → LaTeX (proof) transcription:

- All **English explanatory text** must be wrapped in:
  - `\mathsf{...}`
- All **mathematical expressions/content** must be wrapped in:
  - `\mathtt{...}`

Purpose: commentary visually distinct from mathematical content, and math is consistently readable.

**Do not** replace this by `\text{\texttt{...}}` for entire equations; keep math in math mode and apply `\mathtt{...}`.

---

### 2) Canonical image → LaTeX (proof) transcription protocol

When I give an image of handwritten math and request transcription:

#### 2.1 Preserve structure exactly

- Keep the **same order** of lines and steps as in the image
- Preserve:
  - Equation numbering `(1), (2), (3), ...` including primes `(2'), (2'')`
  - Labels: “Goal”, “Sub.”, “Therefore”, “CASE I / CASE II”, etc.
  - Arrows: `\Rightarrow`, biconditionals, and any logical markers like `\therefore`
- Do **not** rephrase or reorder unless I explicitly ask for a rewrite

#### 2.2 Indentation + alignment conventions (visual layout)

- Use `aligned` for multi-line derivations
- Indent implication chains so derived steps sit **under** the step that produced them
- Align continuation equal signs using manual spacing:
  - `\quad`, `\qquad`, `\,`
- Any line containing `\Rightarrow` must be indented so it sits visually under the block above it (nested proof look)

#### 2.3 “∴” conclusion rule

- The `\therefore` line must be **indented** relative to the reasoning that leads to it (not flush-left like a new paragraph)

#### 2.4 Parenthetical comment alignment

- Parenthetical comments like `(simpl.)`, `(applying triangle inequality)`, etc., should align consistently within the block when feasible (use spacing like `\qquad`)

#### 2.5 Correct mistakes—but never silently

- If a math/logic mistake is detected, correct it, but also include an explicit note:
  - “Correction: … because …”
- Do not “quietly” change content without flagging it

---

### 3) Theorem/definition formatting (“markdown + latex thm”)

Callouts are used **only** for:
1) theorem/definition-style blocks (“markdown + latex thm”)
2) proof outlines if I explicitly request an outline

#### 3.1 Exact callout template

- Outer callout: `[!note]+ **Title**`
- Nested callout: `[!warning]+ **IF**` with bullet hypotheses
- Blank line
- Nested callout: `[!tip]+ **THEN**` with conclusion in `$$...$$`

**Rendering requirement:** include a blank line between nested callouts so Obsidian renders them correctly.

#### 3.2 Notes sub-callout

- Include “Notes” only when genuinely needed, not by default.

---

### 4) Tables standard (Inequalities/absolute value) — “Table Formatting v2”

When asked for inequality/absolute value property tables:

- 3 columns: `# | Name/Theme | Property`
- Hypotheses inside property cell use multi-line:
  - `\begin{aligned}...\end{aligned}`
- Use `<br>` for line breaks inside table cells
- Use `\lvert \cdot \rvert` for absolute values in tables
- Use `\dfrac` (never `\tfrac`)
- Group variants under one number with:
  - `» **k.i**` + *italic short name in parentheses*
- Provide separate strict/non-strict/mixed tables when relevant
- Themes order:
  - axioms/transitivity → addition/subtraction → scalar multiplication → products/powers → division/reciprocals
- Common pitfalls to avoid:
  - incorrect subtraction pairing (“cross subtraction”)
  - incorrect strictness in division rules (depends on hypotheses)

---

### 5) Propositional logic proofs (O’Leary style)

For O’Leary propositional logic proofs:

- Use line-by-line natural deduction
- Numbered lines and nested subproofs
- Rules/labels: MP, simp, conjunction intro/elim, DP (Deduction Principle)
- Match the established layout style (not paragraph proofs)

If asked for TikZJax:

- Include `\usepackage{...}` and wrap in `\begin{document}...\end{document}`

### 7) “Do not do this” list (hard dislikes)

- Do not use `\tfrac`
- Do not mix fonts when image→LaTeX proof style is requested
- Do not silently reorganize proofs or “improve” by rearranging steps
- Do not overuse callouts; only use them where specified
- Do not add AI-ish filler or motivational padding
- Do not ask repeated clarifying questions when a best-effort answer is possible

---

### 8) Operational workflow checklist

#### A) When I provide handwritten notes (image)

1. Identify structure (headers, cases, goals, equation numbers)
2. Transcribe line-by-line, preserving order and labels
3. Apply indentation/alignment rules (nested `\Rightarrow`, aligned `=`)
4. Wrap:
   - English commentary in `\mathsf{...}`
   - Math content in `\mathtt{...}`
5. Scan for errors; if found, flag corrections explicitly
6. Output as paste-ready Obsidian code when asked (fenced `markdown` block)

#### B) When I say “it renders wrong in Obsidian”

- Assume Obsidian parsing issues first:
  - `|` inside tables → convert to `\lvert \rvert`
  - missing blank lines between nested callouts
  - display math fence issues (`$$...$$` only)
  - KaTeX macro incompatibilities (red function names)
- Fix with Obsidian-safe forms:
  - `\operatorname{...}` where needed
  - ensure definitions/macros are placed where Obsidian will actually apply them (not as plain text in the note)

#### C) When I ask “just the code”

- Provide only the code in a fenced `markdown` block
- Minimal/no prose outside the block

---

### 9) Manual performance habit

- Gentle reminder roughly every ~50 messages to start a new chat (Obsidian + transcription work can slow long threads).
