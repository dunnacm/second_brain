- When I ask for paste-ready Obsidian content: return it inside fenced blocks:
    
    - One fenced `markdown ...` block per requested artifact.

## Callouts policy (theorem/definition notes)

- Callouts used ONLY for:
    
    1. theorem/definition blocks (“markdown + latex thm”), and
        
    2. proof outlines (only when requested).
        
- Callout syntax: always blockquote form:
    
    > [!note]+ **Title**
    > 
    > > [!warning]+ **IFF**
    > > 
    > > - (bulleted hypotheses)
    > >     
    > > - (IFF condition in inline math)
    > >     
    > 
    > > [!tip]+ **THEN**  
    > > .........
    
- Include a blank line between the [!warning] block and the [!tip] block for Obsidian rendering.
    
- Do NOT put full proofs or ordinary remarks inside callouts unless explicitly requested.
    
- Kaizen rule (semantic-consequence callouts): place setup lines (e.g., “$p,q,r$ are propositional forms”) inside the **IFF** section as bullet hypotheses; format the IFF condition as inline math; reserve display math for THEN.
    

## Image → LaTeX (proof) transcription protocol (single aligned block)

### Output formatting

- Entire proof in exactly one block:  
    ...\begin{aligned} ... \end{aligned}...​
    
- Single alignment column: exactly one `&` per row (no multi-`&` grids).
    
- Every row contains an `&`:
    
    - Numbered row: `(n)\quad & ...`
        
    - Narrative row: `& ...`
        
- Default spacers: \[12pt], \[18pt], \[22pt] (avoid larger unless the source demands).
    

### Alignment + indentation

- Use manual spacing (\quad, \qquad, ,) to visually align continuation `=` signs and right-side comments when needed.
    
- Implication nesting must be visibly hierarchical:
    
    - `& \Rightarrow (k)\quad ...`
        
    - `& \qquad\ \Rightarrow (k+1)\quad ...`
        
    - `& \qquad\ \qquad\ \Rightarrow (k+2)\quad ...`
        
- Continuation/evaluation lines are indented ONLY if they are true continuations under `=` or subordinate to an implication; otherwise keep base alignment.
    

### Kaizen (gold-standard matching)

- If I provide a “closer to what I needed” LaTeX block, treat it as gold standard:  
    preserve step labels (including primes), wording, punctuation, spacer pattern, and structure; do not restructure; change only what’s necessary for correctness or explicitly requested.
    

### Mandatory math-coherence scan

- Keep defining relations consistent (signs/radicands).
    
- Differentiation steps must match prior expressions.
    
- Substitutions must match the integrand and the final form.
    
- If the source image contains a math mistake: explicitly flag + correct; do not silently propagate.

## \mathtt typography protocol (principled)

### Governing principle

Keep convention-bound objects in standard math fonts; put only typography-discretionary tokens into `\mathtt{...}`.

### Do NOT wrap in \mathtt{...} (convention-loaded)

- `\mathbb{R}, \mathbb{N}, ...` (sets)
    
- `\mathcal{D}, \mathcal{R}` (domain/range notation)
    
- `C(\mathbb{R})`, `C(\mathbb{R},\mathbb{R})`, etc. (function spaces)
    

### DO wrap in \mathtt{...} (typography-discretionary)

- function-name tokens when you want the “name token” styled (e.g., `\mathtt{sinh}`, `\mathtt{cosh}`, `\mathtt{tanh}`)
    
- narrative labels/text tokens (“Sub.”, “Thus”, “From…”, etc.) when they appear as text.
    

### No style spread

Apply `\mathtt` deliberately; do not let it spread onto nearby convention-bound symbols unless explicitly requested.

### Narrative rows inside aligned

Do NOT wrap an entire narrative row in `\mathtt{...}` if it contains convention-bound symbols. Wrap only the text tokens, keep symbols outside. Example pattern:  
`& \mathtt{Thus } \mathcal{D}_{\mathtt{f}}=\mathbb{R} \mathtt{ and } \mathtt{f}\in C(\mathbb{R}).`

### Domain/range/continuity shorthand (example pattern)

- `\mathcal{D}_{\mathtt{f}}=\mathbb{R}\ \bigl(= (-\infty,\infty)\bigr)`
    
- `\mathcal{R}_{\mathtt{f}}=\mathbb{R}\ \bigl(= (-\infty,\infty)\bigr)`
    
- `\mathtt{f}\in C(\mathbb{R})`
    

### Hyperbolic rendering robustness

If `\sech`, `\csch`, etc. render unreliably, prefer:

- `\mathtt{sech}`, `\mathtt{csch}`, `\mathtt{coth}` (and inverses as `\mathtt{sech}^{-1}`, etc.), or
    
- `\operatorname{sech}`-style forms.  
    Match diagram labels like “secht/cscht” via `\mathtt{sech}\,t`, `\mathtt{csch}\,t` as appropriate.
    

## Conditionals parsing (kaizen)

For parsing-convention statements, use symbol-level monospace:

- Wrap only propositional-variable tokens in `\mathtt{...}`, leaving connectives like `\to` and parentheses normal.
    
- Keep explanatory phrase in `\text{...}`.  
    Example:  
    a→b→c is parsed as a→(b→c).\mathtt{a}\to\mathtt{b}\to\mathtt{c}\ \text{is parsed as}\ \mathtt{a}\to(\mathtt{b}\to\mathtt{c}).a→b→c is parsed as a→(b→c).

## Diagram refinement protocol (photo/scan → clean “PDF screenshot” look)

- Geometric correction first:
    
    - make x-axis perfectly horizontal,
        
    - make y-axis perfectly vertical,
        
    - intended horizontal/vertical construction lines must become horizontal/vertical.
        
- Background normalization: whiten paper, remove specks without erasing fine strokes.
    
- Line clarity: light sharpening after denoise; avoid thickening/haloing.
    
- Shading cleanup: even out shaded regions, preserve crisp boundaries.
    
- Crop + margins: tight crop to content with clean margins.
    
- Output: high-resolution PNG suitable for direct paste into Obsidian.

## Rule of indentation (kaizen; critical)

When I say **“rule of indentation”**, do this:

Within each equation/derivation set, align the step markers by placing `&` **immediately before** the marker on **every line** (e.g., `\Leftrightarrow`, `\Rightarrow`, `=`, etc.). Continuation lines use an empty left column so the marker stacks vertically without manual `\qquad` spacing.
